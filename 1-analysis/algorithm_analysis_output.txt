
============================================================
ALGORITHM ANALYSIS: t(n) Resource Function Examples
============================================================

============================================================
O(1) - CONSTANT TIME
============================================================

1. GET FIRST ELEMENT - t(n) = 1 = O(1)
----------------------------------------
   n =    10  ->  t(n) = 1 operation (always 1)
   n =   100  ->  t(n) = 1 operation (always 1)
   n =  1000  ->  t(n) = 1 operation (always 1)
   n = 10000  ->  t(n) = 1 operation (always 1)

2. ARRAY INDEX ACCESS - t(n) = 1 = O(1)
----------------------------------------
   n =    10  ->  t(n) = 1 operation (always 1)
   n =   100  ->  t(n) = 1 operation (always 1)
   n =  1000  ->  t(n) = 1 operation (always 1)
   n = 10000  ->  t(n) = 1 operation (always 1)

3. SIMPLE ADDITION - t(n) = 1 = O(1)
----------------------------------------
   n =    10  ->  t(n) = 1 operation (always 1)
   n =   100  ->  t(n) = 1 operation (always 1)
   n =  1000  ->  t(n) = 1 operation (always 1)
   n = 10000  ->  t(n) = 1 operation (always 1)

============================================================
O(log n) - LOGARITHMIC TIME
============================================================

4. BINARY SEARCH - t(n) = log2(n) = O(log n)
----------------------------------------
   Halves search space each iteration
   n =    10  ->  t(n) =  4 comparisons  (log2(10) = 3.3)
   n =   100  ->  t(n) =  7 comparisons  (log2(100) = 6.6)
   n =  1000  ->  t(n) = 10 comparisons  (log2(1000) = 10.0)
   n = 10000  ->  t(n) = 14 comparisons  (log2(10000) = 13.3)

============================================================
O(n log n) - LOG-LINEAR TIME
============================================================

5. MERGE SORT - t(n) = n * log2(n) = O(n log n)
----------------------------------------
   n operations per level * log2(n) levels
   n =    10  ->  t(n) =     34  (10*3 = 33)
   n =   100  ->  t(n) =    672  (100*7 = 664)
   n =  1000  ->  t(n) =   9976  (1000*10 = 9966)
   n = 10000  ->  t(n) = 133616  (10000*13 = 132877)

6. LOG-LINEAR LOOP - t(n) = n*(log2(n)+1) = O(n log n)
----------------------------------------
   n outer iterations * (log2(n)+1) inner iterations
   n =    10  ->  t(n) =     40  (10*4 = 40)
   n =   100  ->  t(n) =    700  (100*7 = 700)
   n =   500  ->  t(n) =   4500  (500*9 = 4500)
   n =  1000  ->  t(n) =  10000  (1000*10 = 10000)

7. HALVING WORK PER LEVEL - t(n) = n*(log2(n)+1) = O(n log n)
----------------------------------------
   n work per level * (log2(n)+1) levels
   n =    10  ->  t(n) =     40  (10*4 = 40)
   n =   100  ->  t(n) =    700  (100*7 = 700)
   n =   500  ->  t(n) =   4500  (500*9 = 4500)
   n =  1000  ->  t(n) =  10000  (1000*10 = 10000)

============================================================
O(n) - LINEAR TIME
============================================================

8. LINEAR SEARCH (worst) - t(n) = n = O(n)
----------------------------------------
   n comparisons (element at last position)
   n =    10  ->  t(n) =    10
   n =   100  ->  t(n) =   100
   n =  1000  ->  t(n) =  1000
   n = 10000  ->  t(n) = 10000

9. SUM OF ELEMENTS - t(n) = 1 + 2n + 1 = 2n + 2 = O(n)
----------------------------------------
   init(1) + loop(2n) + return(1)
   n =    10  ->  t(n) =    22  (2*10+2 = 22)
   n =   100  ->  t(n) =   202  (2*100+2 = 202)
   n =  1000  ->  t(n) =  2002  (2*1000+2 = 2002)
   n = 10000  ->  t(n) = 20002  (2*10000+2 = 20002)

10. FIND MAXIMUM - t(n) = 1 + (n-1) = n = O(n)
----------------------------------------
   init(1) + comparisons(n-1)
   n =    10  ->  t(n) =    10  (1+9 = 10)
   n =   100  ->  t(n) =   100  (1+99 = 100)
   n =  1000  ->  t(n) =  1000  (1+999 = 1000)
   n = 10000  ->  t(n) = 10000  (1+9999 = 10000)

11. COUNT OCCURRENCES - t(n) = 1 + n = n + 1 = O(n)
----------------------------------------
   init(1) + comparisons(n)
   n =    10  ->  t(n) =    11  (1+10 = 11)
   n =   100  ->  t(n) =   101  (1+100 = 101)
   n =  1000  ->  t(n) =  1001  (1+1000 = 1001)
   n = 10000  ->  t(n) = 10001  (1+10000 = 10001)

12. CHECK IF SORTED - t(n) = n - 1 = O(n)
----------------------------------------
   n-1 adjacent pair comparisons
   n =    10  ->  t(n) =     9  (10-1 = 9)
   n =   100  ->  t(n) =    99  (100-1 = 99)
   n =  1000  ->  t(n) =   999  (1000-1 = 999)
   n = 10000  ->  t(n) =  9999  (10000-1 = 9999)

13. REVERSE ARRAY - t(n) = n/2 = O(n)
----------------------------------------
   n/2 swaps (left and right pointers meet)
   n =    10  ->  t(n) =     5  (10/2 = 5)
   n =   100  ->  t(n) =    50  (100/2 = 50)
   n =  1000  ->  t(n) =   500  (1000/2 = 500)
   n = 10000  ->  t(n) =  5000  (10000/2 = 5000)

14. FACTORIAL - t(n) = n = O(n)
----------------------------------------
   n multiplications (1*2*3*...*n)
   n =     5  ->  t(n) =     5
   n =    10  ->  t(n) =    10
   n =    15  ->  t(n) =    15
   n =    20  ->  t(n) =    20

============================================================
O(n^2) - QUADRATIC TIME
============================================================

15. NESTED LOOPS - t(n) = n * n = n^2 = O(n^2)
----------------------------------------
    n outer * n inner iterations
    n =  10  ->  t(n) =   100  (10*10 = 100)
    n =  50  ->  t(n) =  2500  (50*50 = 2500)
    n = 100  ->  t(n) = 10000  (100*100 = 10000)
    n = 200  ->  t(n) = 40000  (200*200 = 40000)

16. BUBBLE SORT - t(n) = (n-1)+(n-2)+...+1 = n(n-1)/2 = O(n^2)
----------------------------------------
    Sum of arithmetic series: (n^2-n)/2
    n =  10  ->  t(n) =    45  (10*9/2 = 45)
    n =  50  ->  t(n) =  1225  (50*49/2 = 1225)
    n = 100  ->  t(n) =  4950  (100*99/2 = 4950)
    n = 200  ->  t(n) = 19900  (200*199/2 = 19900)

17. TRIANGULAR LOOP - t(n) = 1+2+3+...+n = n(n+1)/2 = O(n^2)
----------------------------------------
    Sum formula: (n^2+n)/2
    n =  10  ->  t(n) =    55  (10*11/2 = 55)
    n =  50  ->  t(n) =  1275  (50*51/2 = 1275)
    n = 100  ->  t(n) =  5050  (100*101/2 = 5050)
    n = 200  ->  t(n) = 20100  (200*201/2 = 20100)

18. PRINT ALL PAIRS - t(n) = (n-1)+(n-2)+...+1 = n(n-1)/2 = O(n^2)
----------------------------------------
    Unique pairs: (n^2-n)/2
    n =  10  ->  t(n) =    45  (10*9/2 = 45)
    n =  50  ->  t(n) =  1225  (50*49/2 = 1225)
    n = 100  ->  t(n) =  4950  (100*99/2 = 4950)
    n = 200  ->  t(n) = 19900  (200*199/2 = 19900)

============================================================
O(n^3) - CUBIC TIME
============================================================

19. THREE NESTED LOOPS - t(n) = n * n * n = n^3 = O(n^3)
----------------------------------------
    n outer * n middle * n inner iterations
    n =   5  ->  t(n) =    125  (5*5*5 = 125)
    n =  10  ->  t(n) =   1000  (10*10*10 = 1000)
    n =  20  ->  t(n) =   8000  (20*20*20 = 8000)
    n =  30  ->  t(n) =  27000  (30*30*30 = 27000)

============================================================
O(2^n) - EXPONENTIAL TIME
============================================================

20. GENERATE ALL SUBSETS - t(n) = 2^n * (n+1) = (n+1)*2^n = O(2^n)
----------------------------------------
    2^n subsets, each checking n bits
    n =  5  ->  t(n) =      192  ((5+1)*2^5 = 192)
    n = 10  ->  t(n) =    11264  ((10+1)*2^10 = 11264)
    n = 15  ->  t(n) =   524288  ((15+1)*2^15 = 524288)
    n = 20  ->  t(n) = 22020096  ((20+1)*2^20 = 22020096)

21. FIBONACCI RECURSIVE - t(n) = ~2^n = O(2^n)
----------------------------------------
    Each call branches into 2 recursive calls
    n =  5  ->  t(n) =       15  (approx 2^5 = 32)
    n = 10  ->  t(n) =      177  (approx 2^10 = 1024)
    n = 15  ->  t(n) =     1973  (approx 2^15 = 32768)
    n = 20  ->  t(n) =    21891  (approx 2^20 = 1048576)
    n = 25  ->  t(n) =   242785  (approx 2^25 = 33554432)

============================================================
O(n!) - FACTORIAL TIME (WARNING: GROWS EXTREMELY FAST!)
============================================================

22. GENERATE ALL PERMUTATIONS - t(n) = ~n! * c = O(n!)
----------------------------------------
    n! permutations, each with constant work
    n = 3  ->  t(n) =     16  (3! = 6)
    n = 5  ->  t(n) =    326  (5! = 120)
    n = 7  ->  t(n) =  13700  (7! = 5040)
    n = 8  ->  t(n) = 109601  (8! = 40320)

23. TRAVELING SALESMAN - t(n) = (n-1)!*(n+1) = O(n!)
----------------------------------------
    (n-1)! routes, each computing n distances + 1 comparison

    n = 4 cities  ->  t(n) =     30  (3!*(4+1) = 30)
    n = 5 cities  ->  t(n) =    144  (4!*(5+1) = 144)
    n = 6 cities  ->  t(n) =    840  (5!*(6+1) = 840)
    n = 7 cities  ->  t(n) =   5760  (6!*(7+1) = 5760)
    n = 8 cities  ->  t(n) =  45360  (7!*(8+1) = 45360)

    WARNING: Factorial grows EXTREMELY fast!
    ----------------------------------------
    5! = 5*4*...*1 = 120
    10! = 10*9*...*1 = 3,628,800
    15! = 15*14*...*1 = 1,307,674,368,000
    20! = 20*19*...*1 = 2,432,902,008,176,640,000

============================================================
SUMMARY: Complete t(n) Formulas & Growth Comparison
============================================================

    Complexity   Complete t(n)              t(10)          t(20)
    -----------------------------------------------------------------
    O(1)         t(n) = 1                   1              1
    O(log n)     t(n) = log2(n)             3.3            4.3
    O(n)         t(n) = n                   10             20
    O(n)         t(n) = 2n + 2              22             42
    O(n log n)   t(n) = n * log2(n)         33             86
    O(n^2)       t(n) = n^2                 100            400
    O(n^2)       t(n) = n(n-1)/2            45             190
    O(n^3)       t(n) = n^3                 1,000          8,000
    O(2^n)       t(n) = 2^n                 1,024          1,048,576
    O(n!)        t(n) = n!                  3,628,800      2.4 * 10^18

    Why we simplify to Big-O:
    -----------------------------------------------------------------
    - t(n) = 2n + 2: at n=1000, the "+2" is only 0.2% of total
    - t(n) = n(n-1)/2: same growth as n^2, just half the constant
    - Big-O captures the DOMINANT term that matters at scale

    Key insight: Algorithm choice matters enormously at scale!

    Real-world implications:
    ---------------------------------------------------------------
    - O(n log n): Can handle millions of items (sorting)
    - O(n^2):     Slows down around 10,000+ items
    - O(2^n):     Impractical beyond ~30-40 items
    - O(n!):      Impractical beyond ~10-12 items

    This is why the Traveling Salesman Problem is so famous -
    there's no known polynomial-time solution for finding the
    optimal route! For 20 cities, brute force needs 2.4 quintillion
    operations.
